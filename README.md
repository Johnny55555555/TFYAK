## 2. Исходный код main.c

Для освоения инструментов был создан файл main.c с функцией square и функцией main.

```c
#include <stdio.h>

int square(int x) {
    return x * x;
}

int main() {
    int a = 5;
    int b = square(a);
    printf("%d\n", b);
    return 0;
}
```

Функция square принимает целое число и возвращает результат умножения аргумента на самого себя. В функции main значение 5 передается в square, после чего результат выводится через printf.

---

## 3. Работа с AST

Для получения AST использовалась команда clang с параметром -ast-dump. Результат был сохранен в файл ast_main.txt.

```bash
clang -Xclang -ast-dump -fsyntax-only main.c > ast_main.txt
grep -A25 "FunctionDecl.*square" ast_main.txt
grep -A45 "FunctionDecl.*main" ast_main.txt
```

**Рисунок 3 — фрагмент AST для функций square и main**

В AST функция square представлена узлом FunctionDecl. Параметр x отображается как ParmVarDecl, а операция x * x — как BinaryOperator. Функция main также представлена как FunctionDecl, внутри которого видны объявления переменных, вызов square и вызов printf.

## 4. Генерация LLVM IR

LLVM IR был создан в двух вариантах: без оптимизации и с оптимизацией уровня -O2.

```bash
clang -O0 -S -emit-llvm main.c -o main_00.ll
clang -O2 -S -emit-llvm main.c -o main_02.ll
```

Для просмотра ключевых инструкций использовалась фильтрация через grep.

```bash
grep -n "define\|alloca\|load\|store\|call" main_00.ll
grep -n "define\|alloca\|load\|store\|call\|printf" main_02.ll
```

<img src="Скриншоты/С5.png" width="700">

**Рисунок 5 — сравнение ключевых инструкций в IR без оптимизации и после -O2**

В IR без оптимизации присутствуют инструкции alloca, store и load. Это значит, что локальные переменные размещаются в памяти, а значения явно записываются и считываются. Также видно, что функция square вызывается отдельно.

После оптимизации -O2 лишние операции работы с памятью исчезают. Вызов square(5) фактически упрощается до готового значения 25, которое передается в printf. Это показывает работу таких оптимизаций, как встраивание короткой функции, свертка констант и удаление лишних операций.

## 5. Оптимизация IR

Сравнение IR до и после оптимизации показывает, что оптимизированное представление становится короче и ближе к SSA-форме. Переменные, которые при -O0 размещались через alloca, после -O2 не требуют явного хранения в памяти.

### Основные изменения после оптимизации:

* удалены лишние alloca, store и load;
* короткая функция square была встроена в место вызова;
* выражение square(5) было вычислено заранее;
* вызов printf получает уже готовый аргумент 25;
* поток управления остался линейным, поскольку в программе нет ветвлений и циклов.

# Ответы на контрольные вопросы

## 1.

Clang — фронтенд LLVM для C/C++. Роль: парсинг, проверка типов, генерация AST и LLVM IR.

## 2.

LLVM — инфраструктура компиляции, предоставляющая независимое от языка и платформы промежуточное представление (IR). Современные компиляторы (Clang, Rustc) генерируют LLVM IR, а затем LLVM оптимизирует и транслирует его в машинный код.

## 3.

AST — высокоуровневое, сохраняет структуру исходного языка (циклы, ветвления). LLVM IR — низкоуровневое, в SSA-форме, предназначено для оптимизаций и машинно-независимого анализа.

## 4.

IR нужно для независимости от языка и архитектуры, повторного использования оптимизаций и упрощения анализа (единое представление).

## 5.

alloca выделяет память на стеке для локальной переменной. Используется в неоптимизированном коде (-O0) и когда необходим адрес переменной; в оптимизированных версиях часто заменяется регистрами (SSA).

## 6.

Оптимизация нужна для ускорения работы программы, уменьшения размера бинарного файла, снижения энергопотребления.

## 7.

SSA-форма (Static Single Assignment) — каждая переменная присваивается ровно один раз. Это упрощает анализ потока данных, позволяет точно отслеживать зависимости и выполнять оптимизации (например, распространение констант, устранение мёртвого кода).

## 8.

CFG — граф, где вершины — базовые блоки (линейные фрагменты), рёбра — переходы между ними. Помогает анализировать возможные пути выполнения, удалять недостижимый код, оптимизировать циклы и т.д.

## 9.

Арифметические операции в LLVM IR типизированы:

```llvm
%res = add i32 %a, %b
%res = mul i32 %a, %b
```

Тип (i32, i64, float) указывается явно.

## 10.

Функции — это независимые единицы компиляции: они имеют свои локальные переменные, изолированы от остальных. Это позволяет оптимизировать их параллельно, а также выполнять межпроцедурные оптимизации (например, inlining) без побочных эффектов.

## 11.

Короткая функция, вызываемая один раз, скорее всего, будет встроена (inlined) — её тело скопируется в место вызова, а сама функция удалится. Это убирает накладные расходы на вызов и может открыть новые возможности для дальнейших оптимизаций.

## 12.

IR проще и не содержит синтаксического сахара, макросов, сложных приведений типов. CFG явно показывает все переходы. Это делает автоматический анализ детерминированным, точным и не зависящим от случайных особенностей исходного текста (например, от форматирования или сложных выражений).
